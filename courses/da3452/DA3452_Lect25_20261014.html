How BERT supports different tasks

BERT gives each input token a vector. We can use these vectors to classify a text, compare two texts, or identify named entities. This page connects those tasks in the order we will study them, then covers token alignment and NER evaluation.

Micro lecture 1

BERT: the encoder

BERT is a bidirectional Transformer encoder. It takes tokenised text and returns one contextual vector for each input token. Each token can use valid input tokens on both sides. In “She sat on the bank of the river”, the later words help us interpret bank.

Original BERT combines token, position and segment embeddings, then applies Transformer blocks. These vectors represent the input. A task head, a prediction layer added for a task, converts them into the required output.

Micro lecture 2

How BERT is trained

Masked language modelling (MLM) selects some token positions and asks the model to predict their original tokens. Selected inputs may be masked, replaced, or left unchanged. Cross-entropy measures the prediction error at those selected positions. Other tokens still provide context and can influence learning.

Original BERT also uses next-sentence prediction (NSP): decide whether the second text segment follows the first in the source document. Both losses train the shared encoder. NSP is a pretraining task; later applications use their own labels.

Read: J&M §§9.3.1–9.3.2

Micro lecture 3

Classifying a text

For sequence classification, the output is one label for the whole input. BERT places a special [CLS] token at the start. A classifier uses its final contextual vector to predict probabilities over task labels.

Example: sentiment classification

The film was wonderful.

Labels: Positive, Negative, Neutral. The target here is Positive.

Task training uses labelled texts. We can train only the head with a frozen encoder, or fine-tune the head and encoder. At inference, the parameters stay fixed.

Classifying a pair of texts

Sentence-pair classification predicts one label for two texts. Original BERT receives [CLS] A [SEP] B [SEP]. The special [SEP] token separates the segments. Segment embeddings identify which segment each token belongs to.

A: Where are the lecture videos?

B: How can I watch previous lectures?

Task: decide whether the questions express the same meaning.

The final [CLS] vector represents the pair for the classifier. Training uses labels for the chosen task. These labels differ from NSP’s IsNext / NotNext labels.

Natural language inference

Natural language inference (NLI) is a sentence-pair task. The first text is the premise; the second is the hypothesis. Judge the hypothesis using the premise.

Premise: A child is holding a red ball.

Micro lecture 6

Named-entity recognition

Named-entity recognition (NER) finds entity spans and assigns their types. A span contains one word or several consecutive words. The task head uses token vectors to predict tags at many positions.

Jane Villanueva (PER) joined United Airlines (ORG) in Chicago (GPE).

PER: person. ORG: organisation. GPE: geopolitical entity. Entity tag sets can differ across datasets.

BIO tags record boundaries: B begins an entity, I continues the same entity, and O marks a word outside any entity. A one-word entity uses B only.

See the BIO tags for this example
WordJaneVillanuevajoinedUnitedAirlinesinChicago
TagB-PERI-PEROB-ORGI-ORGOB-GPE

Read B-PER followed by I-PER as the complete person span Jane Villanueva. B-GPE starts the one-word place name Chicago.

BERT uses subword tokens, while NER annotations usually label words. The next micro lecture explains how to align them. We then evaluate complete entity spans and their types.

Read: J&M §§9.5.1–9.5.4

The encoder supplies contextual vectors. The task determines which vectors we use and which labels we predict.

Micro lecture 7

Tokenization and NER

NER datasets usually give a tag for each word. BERT receives WordPiece tokens. A word can split into several pieces, so the training labels and the model's input positions need to be aligned.

Book example: Mt. Sanitas (LOC) is in Sunshine Canyon (LOC).

J&M shows one alignment method: during training, copy a word's gold tag to every piece of that word. A gold tag is the reference label in the annotated dataset.

The ## prefix marks a continuation piece in WordPiece. It is not part of the original text. Actual splits depend on the tokenizer.

During decoding, the book's simple method uses the first subword's predicted tag as the tag for the whole word. Thus Mt supplies the tag for Mt., and San supplies the tag for Sanitas.

Recover one tag per word before extracting entity spans. The repeated B-LOC training tags for Mt and . belong to one annotated word; they do not mean that the word contains two entities.

Other alignment choices

Some approaches supervise only the first piece of each word. Others combine subword scores when recovering a word label. The training and decoding rules must be stated and used consistently.

Read: J&M §9.5.3, “Tokenization and NER”, pp.240–241, Eq. 9.9

Micro lecture 8

Evaluating named-entity recognition

Compare predicted entities with the human annotation. On this page, we use exact span-and-type matching: both the complete span and its entity type must match.

  • True positive (TP): a predicted entity has an exact gold match.
  • False positive (FP): a predicted entity has no exact gold match.
  • False negative (FN): a gold entity has no exact predicted match.

Jane Villanueva joined United Airlines in Chicago.

Gold entityPredictionResult
Jane Villanueva (PER)Jane (PER)Wrong boundary: 1 FP and 1 FN
United Airlines (ORG)United Airlines (ORG)Exact match: 1 TP
Chicago (GPE)No entity predictedMissed entity: 1 FN

There are 3 gold entities and 2 predicted entities. The counts are TP = 1, FP = 1 and FN = 2. Predicting Jane misses the complete gold name and also introduces an unmatched predicted span.

Precision

How many predicted entities are correct?

P=TPTP+FP

1 / 2 = 0.50

Recall

How many gold entities were recovered?

R=TPTP+FN

1 / 3 ≈ 0.333

F1

The harmonic mean of precision and recall.

F1=2PRP+R

2 TP / (2 TP + FP + FN) = 2 / 5 = 0.40

O tokens are not entities and do not enter these entity counts. A wrong entity type also fails an exact match, even when the boundary is right. Token accuracy can hide missed entities when many words have O tags.

Comparing two NER systems

J&M §9.5.4 also mentions paired bootstrap and randomization tests, with methods in §4.11. These help assess whether an observed F1 difference is statistically significant. Use the same test data, label set and matching convention when comparing systems.

Read: J&M §9.5.4, p.241. This worked example states the exact entity-matching convention explicitly.
