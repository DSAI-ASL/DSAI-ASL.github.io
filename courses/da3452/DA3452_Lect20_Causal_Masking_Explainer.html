Causal masking: a worked example

This page computes decoder self-attention for the query at “cat”. It does the calculation without a causal mask and then with one, and shows where the unmasked version uses information from “slept”.

1

The task at position 3

We translate बिल्ली सोई। into “The cat slept.” During training the decoder receives the whole target sentence at once, shifted right by one position (teacher forcing). Each position must predict the token one step ahead.

Position 3 holds cat and must output slept. During training, slept is also in the input at position 4. At inference it is not, because it has not been generated yet. Position 3 must therefore not use position 4.

2

Embeddings and projection matrices

Each token gets a 3-dimensional binary embedding xj. Only slept has feature 3 equal to 1, so feature 3 identifies slept.

PositionTokenxj (1×3)feature 1feature 2feature 3

The same three projection matrices are applied at every position. Each matrix has a simple effect.

WV copies feature 3 into value coordinate 2. So if an output has a nonzero coordinate 2, it used the value of slept. We use coordinate 2 to detect leakage.

Positional encodings are omitted to keep the arithmetic simple. The mask works the same way with them.

3

Compute query 3

Multiply the embedding at position 3 by WQ. Each entry of the result is the dot product of the row vector with one column of the matrix.

This query is compared with the key of each position it is allowed to use.

4

Compute keys and values

Each position has a key, which is compared with queries, and a value, which is combined into the output. Here the key keeps features 1 and 2, and the value keeps features 1 and 3.

PositionTokenxjkj = xjWKvj = xjWV

cat and slept have the same key. So without a mask, query 3 gives them equal weight.

5

Compute scores for query 3

The raw score is the dot product q3·kj. We then divide by √dk = √2. This is the standard scaling in Transformer attention.

Keyq3 · kjRaw scoreScaled (÷√2)

The mask has not been applied yet. The score for slept is computed like the others. The mask is applied in the next step.

6

Softmax and output, without and with the mask

Softmax converts scores into weights that sum to 1. The mask is applied before softmax: scores for future positions are set to −∞. Since e−∞ = 0, those positions get zero weight, and the other weights are renormalized.

7

Why the leak matters

Without the mask, the output at position 3 has 0.366 in coordinate 2, which comes only from slept. A decoder trained this way can learn the rule “if coordinate 2 is positive, predict slept.” Training loss becomes low.

At inference the decoder generates left to right. When position 3 predicts the next word, position 4 does not exist yet, so coordinate 2 is 0. The rule learned in training no longer applies, and predictions are poor. The training loss does not show this problem.

With the mask, position 3 uses only ⟨BOS⟩, The and cat, in both training and inference. All positions are still computed together in one matrix multiplication. The mask only sets some weights to zero.

9

Check yourself

Why is position 3 allowed to attend to itself?

Its target is the next token, slept. When slept is predicted, cat has already been generated, so cat is available at inference. The mask removes positions j > i, not j ≥ i.

Query 4 (slept) has 0.366 in coordinate 2 even with the mask on. Is that a leak?

No. The input at position 4 is slept and its target is the period, so slept is part of its prefix. A leak means weight on a position after the query, and query 4 has none. Coordinate 2 indicates a leak only for queries 1–3.

Query 1 is [0 0], so it scores every key as 0. Can it still leak?

Yes. Equal scores give weights of 1/4 each, including on slept, and the output is [0.75 0.25]. Any nonzero weight on a future position adds its value to the output. With the mask, query 1 sees only ⟨BOS⟩ and outputs [0 0].

What goes wrong if you mask by setting forbidden scores to 0 instead of −∞?

e0 = 1, so future positions still get weight. For query 3, slept gets weight 0.123 and coordinate 2 is 0.123. Use −∞ (or a large negative number) so the exponential is 0.

Why not just zero the weights after softmax?

This removes the leak, but the remaining weights no longer sum to 1. For query 3 they sum to 0.635, and the output is [0.546 0]. Each row is scaled by a different amount. Masking before softmax renormalizes the weights: 0.140, 0.284, 0.576.

A real decoder has several layers. Is it enough to mask only the first?

No. Each self-attention layer combines positions again. If layer 2 were unmasked, position 3 could use the layer-1 output at position 4, which contains slept. With every decoder self-attention layer masked, the representation at position i depends only on positions 1…i. Cross-attention to the encoder needs no causal mask, because the full source sentence is available at inference.
